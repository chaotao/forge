# forge · L3 模块设计 —— `observer`

> 层级：**L3**。上游 = **L2 概要架构与模块划分**（`02-architecture.md`）。
> 本文件写 `observer` 的**核心设计**；**实现以 `forge/observer.py` 为准**。

---

## 1. 职责与边界

**一句话**：`observer` 把 **forge 之外**的运行状态（aiwf / git / 文件系统）读成**统一的结构化视图**，**现读现算、一个字节都不写**（L2 §2.2 不变量 2 · §2.3②）。

|         | 内容                                                                                                                                                                                                                           |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **做什么** | ① 调**外部工具的 CLI**（本轮 = `aiwf`，**一律 `--json`**），读**运行状态**<br />② 把结果归一成**读时投影**（`AiwfSection` 等，§3）<br />③ 失败时返回**原因**而不是抛错（§6）                     |
| **不做**  | ① **不写任何东西** —— 不落盘、不缓存、不生成快照；★ **也不写 aiwf 的任何文件**（工作流定义 `.aiwf/workflows/` · run 快照 `.aiwf/runs/*/workflow.json` · 安装记录）—— 那是 **aiwf 的地盘**（L2 §4.3），**兼容 / 迁移归 aiwf**（L2 §2.3②「什么都不存」· §2.4 硬线 2）<br />② **不做语义判断**（"该不该介入"归 agent，L1 约定 **B**）<br />③ **不碰 forge 自有数据**（那是 `store`）<br />④ **无 CLI · 无 `--json`**（不给 agent / 人直接面，§7）<br />⑤ 本模块**不 import** 任何用例模块 |

**模型归属**（依 L1 约定 **C**：「模型先行」）—— `observer` **没有落盘模型**：

| 数据                               | 模型由谁定义            | 落盘？                 | 进 `forge/schemas/`？ |
| -------------------------------- | ----------------- | ------------------- | ------------------- |
| 外部运行状态（aiwf / git / 文件系统）        | **本文件**（§3 的读时投影） | **❌ 不落盘**（L2 §2.3②） | **❌ 不**（不是 `kind`）  |
| forge 自有数据（`projects` / `lock`…） | `store` / 各用例 L3  | ✅                   | ✅                   |

> **为什么没有落盘模型**：`observer` **什么都不存** —— 它的产出是**读时投影**（L1 约定 **D2**「派生的不落盘」）。  
> 故 L1 约定 **C** 的「先有 schema」在这里的落点是：**先定投影的形状**（§3），但**不写 schema 文件、不进 `store` 的 `kind` 表**（`03-store` §6.2 的接入公式只覆盖**写数据的模块**，`08` §5.1 同款结论）。

## 2. 数据源与范围

**判定依据 = L2 §2.5：数据访问层按「数据所有者」增长，`observer` 是「外部」那一格的唯一读口。**

| 数据源       | 状态        | 本轮 | 依据                                              |
| --------- | --------- | -- | ----------------------------------------------- |
| **aiwf**  | ✅ **本轮做** | ✅  | `08` §7 ①（**本轮必做**）                              |
| **git**   | ⏸ **延后**  | —  | `08` §7 ③ + §9 **T9**（当前无消费者）                   |
| **路径可达性** | ⏸ **延后**  | —  | `08` §7 ② + §9 **T9**（当前无消费者）                   |

★ **适配器扩展点**（L2 §2.5 要求「`observer` 须留适配器扩展点」）：**加一个数据源 = 加一个内部适配器函数 + `Observation` 多一个字段**（§5），**不动对外接口**。

| 步 | 接一个新数据源（如 `git`）要做的事                                           |
| - | -------------------------------------------------------------- |
| ① | 写内部适配器 `_observe_git(root) -> GitSection`                      |
| ② | 在 `observe()` 里加一行，塞进 `Observation.git`                        |
| ③ | **对外接口 / 消费方调用方式不变**（`Observation` 是**按数据源分字段**的容器，A3：加字段向后兼容） |

> ★ **这**不&#x662F;**"数据访问层增长"** —— 模块构成（仍是 `store` + `observer`）不变（L2 §2.5：新增数据源 = **适配器内部**扩展）。真正的增长只有"出现新的**数据所有者**"。

## 3. 模型（**读时投影**，不落盘）

> 依 L1 约定 **C**：先定形状。以下**不是** schema 文件，而是 `observe()` 返回值的**结构语义**（L2 §2.5：对外只暴露结构语义）。

### 3.1 `AiwfSection` —— 一个项目的 aiwf 现读状态

```
AiwfSection {
  workflows:   int | null       # 已装工作流数（`workflows --json` 数组长度）
  runs_total:  int | null       # 顶层 run 总数（`runs list --json` 数组长度）
  running:     [AiwfRun]        # 运行中的 run（status == "running"）；读不到 → []
  last:        AiwfRun | null   # 最近一次「已结束」的 run（completed / failed）
  error:       string | null    # 本路读不到时的原因（§6）；能读到 = null
}
```

**★ 三条口径**：

| # | 口径                                                                                                    | 依据                           |
| - | ----------------------------------------------------------------------------------------------------- | ---------------------------- |
| 1 | **数据字段只报"实读到的"**；**读不到 → `null`（不取 `0`）** —— `0` 会被读成「**真的没有**」，那是**谎报**                              | L1 **H2**（无歧义）· L2 §2.4 硬线 2 |
| 2 | **"非 aiwf 项目"不是错误** —— aiwf 自己返回 `(no workflows…)` / `(no runs)`、rc=0 ⇒ **照实为零**（`0` / `[]` / `null`） | `08` §4.3.2 ③（实测）            |
| 3 | **`error` 非空 ⇒ 该段只显示 `error`**，数据字段一律 `null`（§6）                                                      | `08` §4.3（单一 `error`）· §6.4  |
| 4 | ★ **`running` 是口径 3 的例外** —— `error` 非空时它给 `[]`（**不是 `null`**）：类型 `[AiwfRun]` 不可空，且口径 3 下消费方**只看 `error`** | §3.1 类型声明 + §6 |

> ★ **`workflows` 与 `runs_total` 的区分价值**（`08` §4.3）：`workflows=0` = **没接流程**；`workflows>0` 且 `runs_total=0` = **装了流程但没跑** —— 实测**只能靠 `workflows` 计数区分**这两态（`runs list` 两者都返回 `(no runs)`，见 §4.4 ③）。

### 3.2 `AiwfRun` —— 一个 run

```
AiwfRun {
  run_id:       string          # `runs list --json` 的 run_id
  workflow_id:  string          # `runs list --json` 的 workflow_id —— ★ 这是**模板 id**，不是实例名
  title:        string          # ★ **实例名**（`runs list --json` 的 title，aiwf `run_title()` 解析好）—— **永不为空**
  status:       string          # ★ aiwf 的词（running / completed / failed …）—— 透传，不翻译（§4.4 §8-14）
  started_at:   string          # `runs list --json` 的 started_at —— ISO 原文，不算「几天前」（L1 G）
  # 以下 4 项来自 runs show --view --json；★ 仅对 running 的 run 取（§4.2）；否则缺省
  stages_done:  int    | null   # --view 里 status=="done" 的阶段数
  stages_total: int    | null   # 阶段总数
  current:      string | null   # 当前阶段名（status=="waiting" 的那个阶段）
  wait:         string | null   # ★ 该阶段的 action.kind（如 review / provide）→「在等谁」
}
```

**★ 口径**：

| # | 口径                                                                                                             | 依据                                                     |
| - | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 1 | **`--view` 派生字段（`stages_*` / `current` / `wait`）可缺省** —— `last`（已结束的 run）**不取 `--view`** ⇒ 这 4 项为 `null`（§4.2）。★ **`title` 不在其列**：它来自 `runs list`，**每条 run 都有** | L1 **A1**（无消费者的字段不空跑）+ `08` §4.3 注（"对**运行中**的 run 追加"） |
| 2 | **`wait` 是 `action.kind` 的透传**，`observer` **只取值、不解释、不拼命令**（如 `review` → 不给 `aiwf review …`）                    | `08` §4.3 末 · §8-13 + L1 **F**                         |
| 3 | **无 `ended_at`** —— `runs list` 只给 `duration`（且 running 时为 `None ms`），**算 `ended_at` 是多余变换**；当前无消费者            | L1 **A1** + `08` §4.5（样本未用它）                           |
| 4 | ★ **`title` 取自 `runs list`** —— aiwf 的 `run_title()` **已解析好**（`view.dynamic_title` → 起跑时的 `record.title` → `run_id`，**永不为空**）⇒ `last` 也**有值**、**不必**为它空跑 `--view`。`observer` **只透传**：不拼名字、不猜，也**不做 `workflow_id` 回退**（那是**模板 id**，不是实例名） | L1 **F**（名字归 aiwf）+ **A1**（不重复实现上游解析）+ **H2**（无来源不猜）+ `08` §4.3 |

### 3.3 为什么不是 schema、不落盘

| 对照                 | `store` 的 `kind`（如 `plans`） | `observer` 的投影（`AiwfSection`） |
| ------------------ | --------------------------- | ----------------------------- |
| 落盘                 | ✅ `.forge/plans.json`       | **❌ 一个字节都不写**                 |
| 进 `forge/schemas/` | ✅（`kind` 由文件名派生）            | **❌ 不是 `kind`**               |
| 谁校验                | `store.validate`（结构层）       | **不校验** —— 外部数据不由 forge 约束    |
| 生命周期               | 持久                          | **一次调用内**（用完即弃）               |
| 依据                 | `03-store` §6.2 / §6.4      | L2 §2.3②「什么都不存」· §2.4 硬线 2    |

> ★ **对"过期副本"的直接保证**：因为**不存**，`workbench` 每次渲染拿到的都是**此刻的实况**（L2 §2.4 硬线 2）—— 缓存就破这条（`08` §8-11）。

## 4. 读取机制（CLI 调用）

### 4.1 调用方式

| 点          | 做法                                                                          | 依据                                        |
| ---------- | --------------------------------------------------------------------------- | ----------------------------------------- |
| 以项目路径为工作目录 | `subprocess.run([...], cwd=<项目路径>)` —— ★ **显式 `cwd=` 参数**，**不用 `os.chdir`** | `08` §4.3.2 ④（aiwf 读 CWD）；`chdir` 有进程级副作用 |
| 采集           | `capture_output=True`（★ **抓 bytes**，解码交父侧 `_decode`）                           | 三条命令均 `--json`（§4.2）      |
| 超时         | 设**超时**（防外部工具卡住整张总览）                                                        | L1 **G**（确定性）；`08` §6.4（一项目坏不拖垮全局）        |
| 退出码        | **不以 rc 判成败** —— aiwf 的 `(no runs)` 是 **rc=0 的正常空返回**（§4.4 ③）               | `08` §4.3.2 ③（实测）                         |
| **环境**      | ★ **清掉 `AIWF_HOME`** —— 它非空时 aiwf 改读那个目录、且**静默返回空**（§4.4 ⑤）   | L1 **H2**（不谎报）                          |
| **编码**      | ★ **子进程设 `PYTHONIOENCODING=utf-8`**；父侧**抓 bytes**，`_decode` 按 `utf-8 → gbk` 兜底（§4.4 ⑥）   | L1 **G**（不假设 locale 默认）/ **H2**                          |

### 4.2 命令序列（逐项目）

| 步 | 命令                                  | 拿什么                                                       | `--json`？                 |
| - | ----------------------------------- | --------------------------------------------------------- | ------------------------- |
| ① | `aiwf workflows --json`             | `workflows`（数组长度 = 已装工作流数）            | **有** ✅ → `json.loads` |
| ② | `aiwf runs list --json`             | `runs_total`（数组长度）· 每行的 `AiwfRun` 基础字段 | **有** ✅ → `json.loads` |
| ③ | `aiwf runs show --view --json <id>` | 对 **`running` 的每个 run** 取 `stages_*` / `current` / `wait` | **有** ✅ → `json.loads` |

> ★ **只对 `running` 追加 `--view`**（`08` §4.3 注）—— **`last` 不取 `--view`**：① `last` 的消费者只要"上次那轮结束了 / 失败了"这个事实（`status` + `workflow_id`）；② `current` / `wait` 对已结束的 run 本就无意义；③ `--view` 是**逐 run 一次子进程**，A1 下不多花。⇒ `AiwfRun` 的 4 个 `--view` 字段对 `last` **缺省**（§3.2）。

### 4.3 JSON 输出形状（三条命令）

三条命令**都走 `--json`** ⇒ `observer` **只做 `json.loads`**，**不解析文本、不切列**。

| 命令 | JSON 形状（实测，§4.4） |
| --- | --- |
| `aiwf workflows --json` | `[{"id": …, "name": …}, …]` |
| `aiwf runs list --json` | `[{"started_at", "run_id", "workflow_id", "title", "status", "duration_ms", "node_count", "parent_run"}, …]`（= 文本表同列，**field-per-column**） |
| `aiwf runs show --view --json <id>` | `--view` 派生对象（`run_id` / `workflow_id` / `title` / `status` / `phase` / `stages[…]`；§3.2 取 **4** 字段） |

| 情形 | 处置 | 依据 |
| --- | --- | --- |
| 空集 → `[]` | `workflows = 0` / `runs_total = 0` / `running = []` / `last = null`（**不是错误**） | §3.1 口径 2 |
| **输出不是合法 JSON** | **不能猜** → `error = "aiwf … --json 输出无法解析"`，该段整体降级（§6） | L1 **H2**（不猜） |

> ★ **`--json` 由 `aiwf` 侧提供**（`workflows --json` / `runs list --json`，均 **field-per-column**）——
> `observer` 侧**无文本解析逻辑**；`--json` 的形状即**上游契约**，其变更属 `aiwf` 语义（L1 **F**）。

### 4.4 ★ 六条实测约束（亲测复核 `08` §4.3.2）

> 这六条是**硬约束**，来自实跑（真项目 `novel_demo` / `drama_demo` / `mc-plus` + 边界探针），**不是推断**。

| # | 实测                                                                                                                                    | 对 `observer` 的约束                                                                         |
| - | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| ① | 盘上 `record.json` 是 **run 诞生快照**（`phase: executing` / `node_runs: []`），与 `runs show` 现算结果（`awaiting_review`）**不一致**                    | ★★ **绝不直读 `.aiwf/` 下任何文件**（含 `record.json`）—— 读它就是读**过期副本**，正面撞 L2 §2.4 硬线 2。**一律走 CLI** |
| ②  | `aiwf workflows --json` / `aiwf runs list --json`（**field-per-column**）· `runs show --view --json` **均支持** | 本路**三条全走 `--json`**（§4.3）—— `observer` 侧**无文本解析** |
| ③ | **无 `.aiwf/` 的项目**（`mc-plus`）与**有 `.aiwf/` 但没跑过的项目** → `runs list` / `workflows` **都 rc=0、返回 `(no runs)` / `(no workflows…)`**        | 「没接流程」与「没跑过」**不能靠报错区分** → 只能靠 **`workflows` 计数**（§3.1）                                   |
| ④ | `aiwf` 读的是 **CWD**（在非项目目录跑 → `(no runs)`，**不报错、静默当空**）                                                                                | ★ **必须显式 `cwd=<项目路径>`**；且**必须把「路径不可达」与「真没跑过」分开**（否则把"读不到"当成"真没有"，正是 L1 **H2** 要防的）       |
| ⑤ | ★ `AIWF_HOME` 非空时 aiwf **改读那个目录**（`aiwf/storage.py:241`：`root or os.getenv("AIWF_HOME", ".aiwf")`），**且静默返回空**（实测：指向空目录 ⇒ `runs list --json` / `workflows --json` 都给 `[]`、rc=0） | ★ **必须清 `AIWF_HOME`** —— 不清就把「读不到」谎报成「什么都没有」（L1 **H2**） |
| ⑥ | ★ Windows 下 aiwf 的**管道 stdout 默认按 locale（`cp936`）**输出中文 —— 父进程按 `utf-8` 严格解码 ⇒ `UnicodeDecodeError`（实测 `0xb6` @ position 47，整条命令被读成「无输出」） | ★ **子进程设 `PYTHONIOENCODING=utf-8`** + 父侧**抓 bytes**、`_decode` 按 `utf-8 → gbk` 兜底 ⇒ **绝不假设子进程 stdout 编码** |

### 4.5 ★ 「路径不可达」与「真没跑过」的判别器（实测）

`observer` 用**三步**做确定性分离（**都不依赖 aiwf 的报错** —— 它根本不报错）：

| 步 | 检查                                                 | 命中 ⇒                               | 实测证据                             |
| - | -------------------------------------------------- | ---------------------------------- | -------------------------------- |
| 1 | `os.path.isdir(project_root)` 为假                   | `error = "项目路径不可达"` —— **不调 aiwf** | ——                               |
| 2 | `subprocess.run(..., cwd=…)` 抛 `FileNotFoundError` | `error = "aiwf 不在 PATH"`           | 探针实测：命令不存在 → `[WinError 2]`      |
| 3 | aiwf 正常返回（rc=0）                                    | **正常零值**（`(no runs)` → 0，**不是错误**） | 实测 `novel_demo` / `mc-plus` 两态相同 |

> ★ **步 1 是关键**：`subprocess.run(cwd=<不存在的路径>)` 在**子进程启动前**就抛 `NotADirectoryError`（WinError 267 —— 实测）——  
> 即**路径不存在 / 不是目录时，aiwf 根本没跑**。所以「不可达」有**确定性信号**，不必依赖 aiwf 的输出（它对此只会静默返回 `(no runs)`，`08` §4.3.2 ④）。  
> 步 1 先 `isdir` 预判 → 与步 2 的命令缺失**分开**，语义清晰。
>
> ⚠ **`observer` 可以碰文件系统**（`isdir`）—— `08` §8-5「不碰文件系统」是**对 `workbench` 的约束**；`observer` 正是**外部状态（含路径可达性）的读口**（`08` §7 ② 就是它将来的活）。

### 4.6 可注入（L1 约定 G：确定性可回归）

| 点         | 做法                                                                     | 为什么                                                    |
| --------- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| CLI 出口可替换 | `observe(project_root, *, runner=_run_aiwf)` —— `runner` 是**唯一的子进程出口** | 测试**桩 JSON 输出**（含空 `[]` / 非法 JSON / 版本差异）⇒ 无需真 aiwf |
| 桩输出形态   | 桩**喂 JSON 文本**（不再喂定宽列）                                     | 与真实 `--json` 同形（L1 **G**）    |

## 5. 接口（对 `workbench` 的**公开读面**）

**本模块对外只暴露一个函数**（`observer` **无 CLI**、**无 `--json`**）：

```
observe(project_root: str, *, runner = _run_aiwf) -> Observation

Observation {
  aiwf: AiwfSection        # §3.1 —— 本轮唯一字段
  # git:  GitSection       # 将来（§2 扩展点）
  # path: PathSection      # 将来（§2 扩展点）
}
```

| 点                | 内容                                                                            | 依据                                |
| ---------------- | ----------------------------------------------------------------------------- | --------------------------------- |
| **方向**           | `workbench` → `observer`（**只读**）—— L2 §4.2 边 **8** / §4.2.1                   | L2 §4.2 边 8                       |
| **粒度**           | **一次调用给一个项目的全部外部状态**（`Observation`）—— 满足 **H3**（一次动作一次调用）                     | L1 **H3**                         |
| **为什么不逐数据源一个函数** | `Observation` 是**按数据源分字段**的容器 → 加数据源**不动接口**（§2 扩展点）；逐源函数会让消费方随源增多而改调用序列      | L2 §2.5 + L1 **A3**               |
| **消费者**          | ★ **只有 `workbench`** —— `observer` 落地后，这一路的信号**只进 `workbench`**，**不新增第二个消费者** | `08` §6.3 / §7 承诺 · L2 §2.2 不变量 2 |
| **失败**           | **从不抛到消费方** —— 错误进 `AiwfSection.error`（§6），`Observation` 照常返回                 | `08` §7 ⑤ + §6.4                  |

> ★ **`AiwfSection` / `AiwfRun` 是 `observer` ↔ `workbench` 的跨模块契约**（L1 **F** 管的"跨模块共用模型"）—— 见 `08` §3.2 / §4.3。  
> **改其形状 = 改对外契约**（同 `07-inbox` §6.2 的 `list_items` / `show_item`）。

## 6. 失败语义

**总则**：任一路（命令 / 解析 / 路径）失败 → **该段整体降级** —— `error` 给原因、**数据字段一律 `null`**、**不抛全局错误**（H2：坏就是坏，但不静默吞）。

| 情形                            | `AiwfSection` 结果                                                        | 依据                        |
| ----------------------------- | ----------------------------------------------------------------------- | ------------------------- |
| **aiwf 不在 PATH**              | `error = "aiwf 不在 PATH"`；数据字段 `null`                                    | `08` §7 ⑤ · §4.4 ②        |
| **项目路径不可达**（不存在 / 非目录）        | `error = "项目路径不可达"`；数据字段 `null`（§4.5 步 1）                               | `08` §4.3.2 ④ · L1 H2     |
| **非 aiwf 项目 / 装了没跑**          | **不是错误** —— `workflows=0` / `runs_total=0` / `running=[]` / `last=null` | `08` §4.3.2 ③（实测）         |
| **`--json` 输出不是合法 JSON**（三条任一） | `error = "…输出无法解析"`；数据字段 `null` —— **不猜**（★ **宁可整段降级，不给半份**） | L1 **H2** + `08` §6.4 |
| **子进程超时 / 其它 `OSError`**      | `error = "…"`；数据字段 `null`                                               | `08` §6.4（一项目坏不拖垮全局）      |

> ★ **为什么"整段降级"而不是"给半份"**：① `AiwfSection` 只有**一个 `error`** 字段（`08` §4.3）；② **半份数据比没有更误导** —— 若 `workflows` 读到了、`runs list` 没读到，报 `workflows=3 / runs_total=0` 会被读成"装了 3 个流程、一个都没跑"，而真相是"根本没读到"（L1 **H2**）。  
> ③ 数据字段取 **`null` 而非 `0`** —— `0` 是**一个事实**（真的没有），读不到**不是**那个事实（§3.1 口径 1）。
> ④ ★ **`running` 例外给 `[]`**（其余数据字段 `null`）—— 见 §3.1 口径 4。
>
> ★ **`observer` 不参与"哪一段坏"的呈现决策** —— 它只如实给 `error`；`workbench` 按 `08` §6.4 渲染（该分区 `error` + 其余照常 + rc=0）。
