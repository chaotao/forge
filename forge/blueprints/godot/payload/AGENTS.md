# AGENTS.md

本文件是这个 Godot 游戏项目里**人与 agent 共用的约定入口**。要改它就单开一次改动说明理由，
别在别处另立一套并行约定。

## 这是个什么项目

一个 Godot 4 单机游戏。工程由 **Godot 编辑器 + Godot AI 插件（MCP）** 支撑 ——
agent 能直接读场景树、建节点、改属性、跑测试、搜工程文件，不必靠猜。

## 先看哪里

| 位置 | 放什么 |
| --- | --- |
| `design/` | 玩法设计 —— 一句话概念 / 核心循环 / 范围（含什么、不含什么）。**方向由人拍板。** |
| `spec/` | 跨文档的技术约定 —— 分层、数据模型、坐标 / ID / 命名。 |
| `tests/` | 无头测试脚本；`tools/` 生成脚本（贴图 / 图标等）。 |
| `.forge/` | 项目状态目录，由 `forge` 维护（`lock.json` 别手改）。 |

目录名只是**建议** —— 按这个游戏的实际需要组织，但「同一份内容只在一个地方是权威」这条不能破。

## 记账：`forge`（`plan` + `inbox` 两本账）

本项目由 `forge` 管着（`.forge/` 是它的状态目录）。**两本账**：`plan` 管「做什么、做到哪、判据是什么」，
`inbox` 管「还没成形的念头 / 体验问题 / 技术债」。游戏开发**计划多、周期长**，这本账正是给它用的 ——
**手上的活做到哪用命令记，别只留在对话里。**

**命令的用法不写在这里 —— 看本项目各 agent 目录里的 `forge` skill**（`plan` / `inbox` / `scaffold` 各一份参考）。
项目侧只守两条：

- **别手改 `.forge/` 下的文件** —— 一律走命令（手改 = 绕过校验 + 多出第二个写者）。
- **Markdown 里不另立台账** —— 一份事实一个位置；状态别抄进聊天记录或新文档。

## 代码约定

- **一个真相源**：可变的游戏状态**只有一处持有**（分层与持有关系写进 `spec/`）。
  视图与物理是**投影**，不得自己再存一份 —— 两份状态迟早对不上。
- **数据与表现分离**：数据模型不依赖场景树；表现层订阅数据的变更信号。
- **不做上帝对象**：新内容优先**新增模块 / 组件**，不往既有大类里堆分支。
- **命名**：GDScript 文件 `snake_case.gd`（与类名同源）；节点 / 类名 `PascalCase`。
- **落盘原子**：写存档 / 资源文件走「临时文件 + 替换」，不原地改半个文件。

## 跑测试 / 生成素材

```bash
godot --headless --path . --script tests/<脚本>.gd          # 无头测试
godot --headless --path . --script tools/<脚本>.gd -- --check   # 生成脚本自检
```

⚠ 无头跑要求本机 `godot` 在 PATH 上；**先跑测试再报完成**，别用「应该没问题」交差。

## 干活时的约定

- **一件事一个位置**：同一份内容只在一个文件里是权威，别处引用它，不复制。
- **写之前先看**：动手前先读现行文件与场景，不靠推断。
- **说结论也说说依据**：报结果时给出实际跑过的命令与看到的东西（截图 / 日志 / 测试输出）。
- **别顺手扩大范围**：范围外的优化先问，不自己决定。

## 不要做

- **不要建 `plan/` · `inbox/` 这类目录** —— 计划走 `forge plan …`，不另立一套并行的台账。
- 不要手改 `.godot/`（编辑器缓存）—— 它由编辑器生成。
- 不要删 `.forge/` —— 它是这个项目的状态目录。
- 不要提交密钥、令牌或本机绝对路径（`export_credentials.cfg` 已在 `.gitignore`）。
