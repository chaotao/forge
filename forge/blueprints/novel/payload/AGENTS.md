# AGENTS.md

本文件是这个小说项目里**人与 agent 共用的约定入口**。要改它就单开一次改动说明理由，
别在别处另立一套并行约定。

## 这是个什么项目

一部长篇小说的创作工作区。**AI 主创、人工验收** —— 创作由 agent 承担，
关键节点（选题、大纲、终审）由人来拍板。

## 创作流程

不自由发挥，由 aiwf 工作流 `std.novel-writing` 驱动，八个阶段：
立项构思 → 世界观构建 → 角色设计 → 故事大纲 → 章节细纲 → 逐章写作 → 修订润色 → 终审定稿。

启动：

```bash
aiwf run std.novel-writing --input-file novel/inputs.json --json
```

入参 5 个（**以工作流自己的 `input_schema` 为准**）：`project_dir` · `genre` ·
`theme` · `target_words` · `inspiration`。

> aiwf 的完整协议（任务包怎么看、`complete` / `check` / `provide` / `review` 各怎么用）
> 在本项目安装的 **`aiwf` skill** 里（`<agent 目录>/skills/aiwf/`）—— **以它为准**，
> 本文件只讲怎么开始。

之后**按每次返回的任务包推进** —— 看 `action.kind` 决定你该干什么：

| `kind` | 你要做的 |
| --- | --- |
| `complete` | 按 `node.prompt` 创作，材料用 `node.inputs`，交付到 `node.output` |
| `check` | 按 `check_request.criteria` 自检产物，给 verdict + reason |
| `provide` | 按 `input_request` 向用户收集信息 |
| `review` | 把产物与要求摆给人 —— **结论必须来自人，不能代批** |

## 文件约定

| 位置 | 谁写 | 说明 |
| --- | --- | --- |
| `novel/` | agent（经工作流） | 创作产物：构思 / 世界观 / 角色 / 大纲 / 细纲 / 正文 |
| `.aiwf/` | aiwf 引擎 | 工作流定义与运行记录；**`runs/` 要进版本库** |
| `.forge/` | forge | 项目状态目录（`lock.json` 别手改） |
| `AGENTS.md` · `README.md` | 人 | 约定与说明 |

- **一次一章，不跳步** —— 正文按细纲逐章推进，别批量补写。
- **改上游要回头对齐** —— 世界观 / 角色 / 大纲是正文的依据，动了它们就检查受影响的章节。

## 进度怎么看

本项目**以 aiwf 工作流为主线** —— 进度看 `.aiwf/runs/` 里的运行记录（跑到哪一阶段、产出了什么），
**默认不另记一套计划**。`forge plan` 那套「计划 → 任务」账本留给**计划多、周期长的开发类项目**；
本项目用它只会多出一份要维护的账。

> 确有多条线并行排期（如同时推进两部小说）时，才可选 `forge plan …` ——
> 命令见本项目各 agent 目录里的 **`forge` skill**。

## 干活时的约定

- **一件事一个位置**：同一份内容只在一个文件里是权威，别处引用它，不复制。
- **写之前先看**：动手前先读现行文件，不靠推断。
- **说结论也说说依据**：报结果时给出实际跑过的命令与看到的东西。
- **别顺手扩大范围**：范围外的优化先问，不自己决定。

## 不要做

- 不要手改 `.aiwf/runs/` 下的记录 —— 那是引擎的审计痕迹。
- 不要删 `.forge/` —— 它是这个项目的状态目录。
- 不要提交密钥、令牌或本机绝对路径。
