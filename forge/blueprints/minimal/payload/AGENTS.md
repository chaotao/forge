# AGENTS.md

本文件是这个仓库里**人与 agent 共用的约定入口**。要改它就单开一次改动说明理由，
别在别处另立一套并行约定。

## 先看哪里

- 仓库里的说明 / 设计文档目录（各项目自定，通常是 `docs/`）。
- 若仓库里有 `.forge/`：那是项目状态目录，由 `forge` 维护。

## 记账：`forge`（可选）

本项目由 `forge` 管着（`.forge/` 是它的状态目录）。**计划多、周期长的开发类项目**才用它
（`plan` 管「做什么、做到哪」· `inbox` 管「还没成形的念头」）；**单一流程 / 轻量项目可以不用**，
进度看各自的产物或运行记录。

**命令的用法不写在这里 —— 看本项目各 agent 目录里的 `forge` skill**（`plan` / `inbox` / `scaffold` 各一份参考）。
项目侧只守两条：

- **别手改 `.forge/` 下的文件** —— 一律走命令（手改 = 绕过校验 + 多出第二个写者）。
- **Markdown 里不另立台账** —— 一份状态一个位置；别把状态抄进聊天记录或新文档。

## 干活时的约定

- **一件事一个位置**：同一份内容只在一个文件里是权威，别处引用它，不复制。
- **写之前先看**：动手前先读现行文件，不靠推断。
- **说结论也说说依据**：报结果时给出实际跑过的命令与看到的东西。
- **别顺手扩大范围**：范围外的优化先问，不自己决定。

## 不要做

- 不要提交密钥、令牌或本机绝对路径。
- 不要删 `.forge/` —— 它是这个项目的状态目录。
