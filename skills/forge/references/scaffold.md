# scaffold —— 立项目与增量对齐

把一份蓝图落成一个能开工的项目骨架、把项目登记进受管清单；已建好的项目可以**对齐到蓝图**。

## 命令

```bash
forge new  <路径> [--blueprint <id>] [--blueprints <dir>] [--alias <名>] [--force] [--dry-run] [--json]
forge sync <路径> [--blueprint <id>] [--blueprints <dir>] [--force] [--dry-run] [--json]
```

| 参数 | 说明 |
| --- | --- |
| `<路径>` | 目标项目根 —— `new` 时**可以还不存在**；`sync` 时必须是**已受管**项目 |
| `--blueprint <id>` | 蓝图 id。`new` 缺省 `minimal`；`sync` 缺省**取受管清单里登记的那个**。内置四个：`minimal`（通用骨架）· `novel`（长篇小说，委托装 `aiwf` skill + `std.novel-writing` 流程）· `drama`（AI 短剧，委托装 `img-prompt` · `comfy` · `aiwf` 三个 skill）· `godot`（Godot 游戏，工程骨架 `project.godot` + 自带 **Godot AI 插件**，不委托） |
| `--blueprints <dir>` | 换一个蓝图库 —— **替换**语义，不叠加 |
| `--alias <名>` | 受管清单里的短名（**只有 `new` 有**），缺省取目录名（重名自动加序号） |
| `--force` | ① 目标已存在且不在 lock 里 → 改判为落；② 对委托项**透传**给上游 |
| `--dry-run` | 只预演（`resolve` + `decide`），**一个字节都不写** |
| `--json` | 机器可读输出 |

退出码：**`0`** 成功 · **`1`** 失败或拒绝（错误信息走 stderr）。

## 两个命令各干什么

| | `forge new` | `forge sync` |
| --- | --- | --- |
| 用途 | 立一个**新**项目 | 把**已受管**项目对齐到蓝图（蓝图后补了项、或要换蓝图） |
| 未受管路径 | 正常落位 + 登记受管 | **拒绝** —— 提示先用 `new` |
| 已受管路径 | 蓝图一致 → **幂等 no-op**；不一致 → **拒绝**并提示用 `sync` | 正常对齐 |
| 换蓝图 | **不做**（不是它的职责） | `--blueprint <id>` **显式**触发 |
| 落位链路 | **同一条**：`preview` → `apply` → 报账 ⇒ 两者都**幂等** | |

**`sync` 只增不删** —— 蓝图里去掉的项**留在项目里**；要不要清掉是**人**的决定，别自行处置。

## 工作方式：先预演，再落位

落位会往目标项目里写文件。**动手前先把变更集呈交给人确认**：

1. `forge new <路径> --dry-run`（或 `forge sync <路径> --dry-run`）→ 拿到变更集，每项一个动作：`写入` / `委托` / `跳过` / `拒绝`；
2. **把结果呈交给人** —— 要落哪些文件、有没有 `拒绝`；
3. 人点头后，去掉 `--dry-run` 执行。

**看到 `拒绝` 不要自己决定。** 它表示目标已存在、而 forge 没装过它。
三条路 —— 改路径 / 删目标 / 加 `--force` ——**都由人选**。

> 真实输出（`--dry-run` 与真跑只差标题行）：
>
> ```
> 预演（未落盘）· 蓝图 demo · 目标 <路径>
>   写入   README.md
>   写入   AGENTS.md
>   委托   skill install forge
>   委托   aiwf wf install std.review-check
> 写入 2 · 委托 2
> ```
>
> `跳过` 的那行会带一句「（目标已存在且在 lock 里）」，`拒绝` 的带「（目标已存在且不在 lock 里）」。

## 落位分两类（决定你该期待什么）

| 蓝图项 | 谁动手 | 落在哪 |
| --- | --- | --- |
| `payload:` | **forge 自己写** | 蓝图声明的项目内相对路径 |
| `skill:<名>` | **委托 `skill install <名>`** 安装 | 由 skill-library 按它自己的 agent 表决定 —— **每个启用 agent 的项目目录** |
| `aiwf:<名>` | **委托 `aiwf wf install <名>`** | `<项目>/.aiwf/workflows/<id>.json` |

两条要紧的：

- **委托项**不可预演 —— `--dry-run` 只告诉你会调哪条命令，**报不出落点**（落点归上游）。
- **委托项不进账** —— 装成了什么样，权威在上游（skill-library 注册表 / aiwf 的 `installed.json`），不在 forge。

## 落位之后

| 产物 | 内容 |
| --- | --- |
| `<项目>/.forge/lock.json` | forge **自己落的**那些（`payload:` 项）；**不含委托项** |
| `<FORGE_HOME>/projects.json` | 受管项目清单 —— `FORGE_HOME` 缺省 `~/.forge/` |

**幂等**：同一路径重跑安全 —— 已落过的一律 `跳过`，**一个字节都不写**。
已受管的路径再跑 `new`，只要蓝图一致就是**幂等 no-op**（不再报错）；**换蓝图**用 `forge sync`。

## 边界（别指望它做更多）

- **不做变量渲染、不做代码生成** —— 落的是**静态内容**；需要因地制宜的部分，**落位之后由你改**。
- **不删任何东西** —— `sync` 只补落、不覆盖、不清理。
- 委托路线要求机器上有 `skill` / `aiwf` 命令在 PATH 上；缺了会**停在那一步**（前面已落的照常保留）。
- **一次落位只关联一个蓝图** —— 多蓝图并存（`add`）还没做（要扩受管清单的模型）。
