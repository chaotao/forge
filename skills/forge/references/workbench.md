# workbench —— 看「到哪了」

**只读视图**：不写任何数据。回答两个问题 ——

| 我想知道 | 命令 | 项目根 |
| --- | --- | --- |
| **这个**项目现在什么状态 | `forge status` | **当前工作目录**（在项目里敲） |
| **所有**项目分别到哪了 | `forge workbench` | 无关 CWD（看全局清单） |

两个命令**同一段渲染**：`forge status` = 一段（本项目），`forge workbench` = 多段串起来。
本项目那段**少一行身份**（路径 + 受管状态还在），其余**逐字同形**。

## 一段长什么样

全局视图 = **顶部一段「最近动态」**（跨项目、按时间降序、≤ 6 行）+ **逐项目若干段**；每段 = **1 行身份 + 3 行分区**，`inbox` / `aiwf` 下可再跟几行：

```text
3 个项目 · 焦点 无
最近动态
  2026-10-10 14:35  drama_demo  ⏳ D01 · 第1集 在等你：review（S1 编剧 · 1/8）
  2026-10-09 21:04  mc-plus     在做 2 项：work-config-panels.TASK-006 自建双足编排演示…
  2026-10-09        mc-plus     记了念头 INB-015 把动力轴做成通用旋转输出，允许在轴上挂载非…
  2026-10-08 16:56  novel_demo  ⏳ 悬疑推理 · 名侦探柯南——单元案件驱动、主角聪… 在等你：review（角色设计 · 2/8）

login · web · /home/me/projects/login
  plan   3 份计划（open 1 · reached 1 · dropped 1）· 任务 12（done 7 · doing 2 · todo 2 · blocked 1）· 上次变动 2026-10-09T21:04:53+08:00
         在做 2  登录模块.T3 实现登录页 · 支付模块.T1 接支付网关
  inbox  5 条（open 4 · handed 1 · dropped 0）· 最近 2026-10-09 · 最老未处理 2026-09-28
         最近加入
           INB-005  登录页报错文案要统一
           INB-004  支付日志缺 request id
           INB-003  README 安装步骤过期
  aiwf   流程 1 · 运行 1 · 运行中 1
         ⏳ D01 · 第1集 在等你：review（登录页验收 · 3/6）
```

- **「最近动态」= 全项目按时间排的一段**（`plan` 最近变动 / `inbox` 最近记的 / `aiwf` 运行中与上轮）—— 想知道「**此刻最该看什么**」就看它。
- `forge status` 去掉第一行里的 `别名 · 蓝图`（路径与「（未受管）」保留），「最近动态」放在**路径行下面**。
- 三个分区各给**分布 + 计数**；`plan` 另给**有界的动态项**（在做 / 卡住），`inbox` 另给**最近加入 3 条**。
- `aiwf` 的 run 显示**实例名**（如 `D01 · 第1集`）—— 名字 **aiwf 已解析好**（起跑时 `aiwf run … --title` 给的；工作流可用 `view.dynamic_title` 覆盖为「产出名」）；★ **老 run**（跑在 `--title` 之前）没有名字 ⇒ 显示它的 **`run_id`**。
- **空也照实说**：`plan 0 份计划 —— 未记账` · `inbox 0 条` · `aiwf 流程 0 · 运行 0 —— 未接流程`。

## 读这些行要留意

| 看到 | 意思 |
| --- | --- |
| **`最近动态`**（置顶一段） | 跨项目按**时间降序**排的最近几件事（≤ 6）：谁在等你、谁在做、最近记了什么念头。**只显示最近的几条**，不是全部历史。 |
| `inbox` 下的 **`最近加入`** | 该项目**最近记的 3 条念头**（`text` 截断到 60 宽）。**要全文 / 全部** → `forge inbox list`。 |
| `aiwf` 那几个字是**实例名**（如 `D01 · 第1集`） | 这是**哪一个 run** —— aiwf 解析好的（起跑名 / 工作流 `view.dynamic_title` 的产出名）；★ **老 run 显示 `run_id`**（它跑的时候还没这概念）。 |
| `⋯ 还有 K 条 → forge plan show` | 动态项**只显示 3 条**。**要明细就跑括号里那条命令** —— 本视图**不是** `plan show` 的替代品。 |
| 某分区 `读取失败：…` | 那一块**坏了**（如数据文件损坏 / 外部工具调不通）。★ **只影响这一块**，别的分区照常；**计数显示为空，不是 0** —— 别把「读不到」当成「真的没有」。 |
| `（未受管）` | 这个目录**没登记**进全局清单。**不报错**：`status` 照常给数据（可能都是空的）。 |
| `aiwf 流程 1 · 运行 0 —— 装了流程没跑` | 装了工作流但没跑过 —— 与「没接流程」是**两个不同状态**。 |
| 时间戳是**原文 ISO** | 引擎**不算「几天前」**，那由你判断。 |

## 边界（别指望它做更多）

- **它不判「要不要你上」** —— 只给事实（计数 / 状态 / 谁在等）。「这算卡住了吗、我该不该介入」是**你的判断**。
- **它不缓存、不落盘** —— 每次都是**此刻实况**（所以别指望它省调用；要省就少看）。
- **它不写任何东西** —— `plan` / `inbox` / `aiwf` 三块数据**各有其主**，它只从**各自主人的读面**取数（`plan.overview()` / `inbox.list_items()` / `observer`），**绝不直读 `.forge/` 或 `.aiwf/`**。
- **明细不在这** —— 要一层层往下看，走 `forge plan show` / `forge plan log` / `forge inbox list`。

## 典型用法

```bash
# 在某个项目里干活，先看一眼它在什么状态
$ cd ~/projects/login && forge status

# 手上几个项目都怎么样了 / 有没有在等我的
$ forge workbench

# 想给别的程序消费（同一份视图，不是原始文件）
$ forge workbench --json
$ forge status --json
```

> `--json` 给的是**渲染用的那份视图**（与文本同源），**不是** `.forge/` 里的原始数据。
> ★ **全局 `forge workbench --json`** = `{focus, projects}` —— **顶部那条「最近动态」不在里面**（它是入口层**读时合成**的，避免同一份数据两处落）；每个 `projects[].recent` 各带一份，需要全局时间线就自己并起来。**本项目 `forge status --json`** = 一个 `ProjectStatus`，**含** `recent`。
