# inbox —— 项目里的念头

把**现在不做、但别忘**的念头记在项目里：记下 → **攒成够格的主题** → 交接出去或丢弃。

> ⚠ 它**不是任务列表** —— 任务归 `plan`（`forge plan …`）。inbox 治「**记住不丢**」，不治「追踪进展」。
> 属于**你当前在推的那份计划**的事 → 直接 `forge plan add`，别记进来。

> 命令要**在项目目录里**跑 —— 项目根 = 当前工作目录（`<项目>/.forge/inbox.json` 就是它的数据）。

## 始终遵守（五条，最重要）

| # | 纪律 | 为什么 |
| --- | --- | --- |
| 1 | **归属先分流** —— 属于**当前在推的那份计划** → 走 `forge plan add <计划>.<任务>`；**只有不属于任何计划、或现在不做**的，才进 inbox | inbox 是**暂存**，不是待办。把该做的塞进来 = 用记录代替推进，`plan` 那边就看不见了。这条**没有必填参数能拦你**，只能靠你自己守。 |
| 2 | **不直读 `.forge/inbox.json`** —— 一律走 `forge inbox list` / `show` | 那是引擎的**存储**。直读拿全量原文（烧 token）、绕过视图的过滤与体量规则，还多出第二个写者。 |
| 3 | **合并要"宁少合、不合错"** —— 没把握就留着（继续独立） | 合错了**没有撤销动作**（见 #5）。源虽留在归档里可查，但活页里那几条已经不在了。 |
| 4 | **合并只在两个时点做** —— ① 人明确要求（"整理下 inbox" / "看看还欠什么"）② **准备把念头提升为需求之前**。★ **不在 `add` 的时候合** | `add` 那一刻你只顾着这一条、**没有全局视角** → 判断质量最低；而 `add` 是**最高频**动作 → 错的代价被放大。合并是**批量动作**，本该一次看全、一次判断。 |
| 5 | **不设人门、也不设撤销** —— 判断完**直接落盘**；合错就 `add` 一条正确的，**不要去改 `.forge/inbox.json`** | 判断归你（引擎只存）；源条目保留在归档里，能查、能重记，但**不提供"撤回"**。 |

## 命令

**写 —— 一个意图一个动词**：

| 你要做的事 | 命令 |
| --- | --- |
| 记一条念头 | `forge inbox add "登录页的报错文案要统一" [--tag 文案] [--source login] [--note "中英混排"]` |
| **整理**：把 N 条攒成 1 条主题 | `forge inbox merge INB-001 INB-002 --text "统一登录页的报错与提示文案"` |
| **交接出去** | `forge inbox hand INB-003 --to "纳入 login 计划"` |
| **丢弃** | `forge inbox drop INB-002 --to "与既有方案重复"` |
| 其余改动（改笔误 / 补标签 / 改出处） | `forge inbox set INB-003 [--text][--tag][--source][--note]` |

**强制项**（不给自己留含糊）：`add` 必给**内容**；
`merge` **源 ≥ 2 条且必须都是「未处理」** + 必给 `--text`；
`hand` / `drop` **必给 `--to`**。

> `--to` / `--source` 是**一段文本**，**不校验**目标是否存在 —— inbox 与 plan 是两个用例，**互不读对方的账**。写"纳入 login 计划"可以，但引擎不会去确认那个计划在不在。
> `set` **不动状态** —— 状态只经 `merge` / `hand` / `drop` 变。
> `--tag` / `--source` / `--note` **给出即替换**（清空传空串），不是追加。

**读 —— 2 个视图**（都不吐原始文件；默认结构化文本，加 `--json` 拿机器可读）：

| 视图 | 给什么 | 默认体量 |
| --- | --- | --- |
| `forge inbox list` | **未处理条目**：`id` / 内容（截断一行）/ 标签 / 日期 | 全量 |
| `forge inbox list --full` | ★ **整理专用**：内容**全文**（仍不给备注） | 全量 |
| `forge inbox list --all` | 未处理 + **已归档**（归档**只给标题行**，`--full` 也压不住） | 全量 |
| `forge inbox show INB-003` | **单条全文**：内容 + 标签 / 出处 / 备注 + 状态 + **去向** | 全量（单条，有界） |

> 引擎**没有**按标签分组的视图（`--tag` 是**过滤**，不是分组）。要判断"哪几条是一件事"，**自己读 `list --full`**。

## 三个场景

### A · 记下（开发中冒出个念头）

0. ★ **先判归属**（纪律 1）：属当前在推的计划 → `forge plan add <计划>.<任务>`，**别进 inbox**。
1. `forge inbox add "…"` —— 一次调用，拿到 `id`。

### B · 交接（人问"看看还欠什么" / 流程收口）

1. `forge inbox list` —— 一眼扫完还悬着什么。
2. `forge inbox show INB-003` —— 要定去向的那条，看全文。
3. **按去向分组呈交**（纳入某计划 / 留给以后 / 丢弃）—— 由人选定。
4. `forge inbox hand INB-003 --to "纳入 login 计划"` 或 `forge inbox drop …`。

### C · 整理 · 合并（人说"整理下 inbox" / **准备提升为需求之前**）

1. `forge inbox list --full` —— **一次看全**，这是判断的原料。
2. **判断**：哪几条是**一件事**？（同一主题 / 同一处体验问题 / 同一模块的相邻改进）→ 合成**一句**表述。
3. `forge inbox merge INB-001 INB-002 --text "…"` —— **一次调用、一次落盘**（原子）。
4. 重复，直到每个主题都够格。
5. 接着往上走：**提升为需求** —— `forge inbox hand <产物> --to "纳入 <计划>"` + `forge plan add <计划> --title … --goal … --criteria …`（两步都由你做，引擎**不替你建任务**）。

> **合并做了什么**：新增 1 条「未处理」条目（你给的整合表述）；源 N 条 → **已交接**，去向写 `并入 INB-XXX`。
> **合并没做什么**：不动模型、不加字段、不新造"已合并"这种状态 —— 源走的就是**已有的「已交接」**。
> **产物与原料在视图上不区分** —— 都是一条普通的未处理条目，**可以再被合并**（链式）。

## 一个真实场景走一遍

```bash
$ forge inbox add "登录页的报错文案要统一" --tag 文案 --source login
已记 INB-001 · 登录页的报错文案要统一

$ forge inbox add "登录失败没有任何提示" --tag 文案
已记 INB-002 · 登录失败没有任何提示

$ forge inbox list --full
念头 2 条（--full）
  INB-001  未处理  登录页的报错文案要统一  #文案  · 2026-10-09
  INB-002  未处理  登录失败没有任何提示  #文案  · 2026-10-09

# 判断：这两条是同一处体验问题 → 合成一条
$ forge inbox merge INB-001 INB-002 --text "统一登录页的报错与提示文案"
已合并 INB-001 + INB-002 → INB-003 · 统一登录页的报错与提示文案
  2 条源已归档（target="并入 INB-003"）

$ forge inbox show INB-001
INB-001 · 已交接 · 2026-10-09
  登录页的报错文案要统一
  tags    #文案
  source  login
  target  并入 INB-003

# 够格了 → 交接出去（再由 plan 建计划/任务，那是另一步）
$ forge inbox hand INB-003 --to "纳入 login 计划"
hand INB-003  未处理 → 已交接  · 纳入 login 计划
```

## 落在哪

| 产物 | 内容 | 谁写 |
| --- | --- | --- |
| `<项目>/.forge/inbox.json` | **全部条目**（未处理 + 已归档同一份，用状态区分） | **只有 `forge inbox …`** |

它在**版本控制里**（可 diff、有历史）—— 所以**永远不要手改它**：
手改 = 绕过引擎校验，且让下一次 `forge inbox` 写的和你看的对不上。

## 边界（别指望它做更多）

- **不跟踪完成** —— 它没有"进行中 / 已完成"。一条念头的终点只有两个：**交出去了** 或 **丢弃了**。
- **不判"哪几条该合"** —— 相似度是语义判断，引擎不碰；它只给你 `list --full` 的原始条目。
- **不做聚类 / 分组 / 排序 / 提醒** —— 没有按标签分组，没有优先级，没有截止日。
- **不建外键** —— `--to` / `--source` 只是文本，不指向也不校验别的数据。
- **没有跨项目 / 无归属的 inbox** —— 它是项目级的（`<项目>/.forge/`）；还没立项的念头目前无处可放。
