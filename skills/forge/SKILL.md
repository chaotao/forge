# forge —— 面向 AI 协作项目的一站式工具

把「项目怎么立起来、手上的活怎么记、几个项目分别到哪了」收在一处，
让人**对全部项目保有全局意识**、推进更高效。

## 用例

**四个全部开放**：`scaffold` · `plan` · `inbox`（这三个**会写数据**）· `workbench`（**只读**，两个视图出口）。

| 用例 | 状态 | 做什么 | 指南 |
| --- | --- | --- | --- |
| `scaffold` | ✅ 开放 | 把一份蓝图落成能开工的项目骨架并登记受管；已建项目**对齐到蓝图**（`new` / `sync`） | [立项目与增量](references/scaffold.md) |
| `plan` | ✅ 开放 | 项目里各份计划的**目标 / 判据 / 状态** + 任务 + 过程记录 | [做计划](references/plan.md) |
| `inbox` | ✅ 开放 | 现在不做、但别忘的念头：记下 · **攒成主题**（合并） · 交接 / 丢弃 | [记念头](references/inbox.md) |
| `workbench` | ✅ 开放 | 看「到哪了」：**本项目**一眼状态（`forge status`，项目根 = CWD）· **跨项目**总览（`forge workbench`）—— 只读 | [看状态](references/workbench.md) |

## 加载顺序

**绝大多数情况读到本页就够了** —— 一级已给出「能不能做、要看哪个文件」。
只有真要动手时，才点开对应的二级指南（如上表那几行）。

## 始终遵守

- **不直接读 `forge` 数据文件**（`.forge/` 下的 `plans.json` / `plan_log.jsonl` / `inbox.json` 等）——
  那是引擎的**存储**。看数据一律走命令的**视图**（如 `forge plan show` / `forge inbox list`）；
  手改文件 = 绕过引擎的校验、多出第二个写者。
- **写动作用语义动词** —— 认领 / 打回 / 完成 / 卡住 / 放弃**先找同名动词**（`claim` / `reject` / `done` / `block` / `drop`），
  攒主题用 `merge`、交接用 `hand` / `drop`；
  `set` 只接其余改动。**轨迹靠动词名区分意图**，用 `set` 绕路会把"打回 vs 完成"抹平。
- **记念头前先分流** —— 属于**当前在推的那份计划**的事 → `forge plan add <计划>.<任务>`，**别记进 inbox**；
  inbox 只收「现在不做 / 不属于任何计划」的。它是**暂存**，不是待办。
- **看状态走 `forge status` / `forge workbench`** —— 它们**只读**，从 `plan` / `inbox` / `observer` 的**读面**取数；
  ★ **明细不在这** —— 要逐份计划 / 逐条念头，仍走 `forge plan show` / `forge inbox list`（本视图**只给有界摘要**）。
- **`scaffold` 落位前先预演**：往目标项目**写文件**的操作，先 `--dry-run` 拿变更集 → 呈交给人 → 人点头后再执行。
- 遇到 `拒绝` **不要自己决定** —— 三条路（改路径 / 删目标 / 加 `--force`）**由人选**。
- forge 只做**确定性**的事（落静态内容、登记清单、记状态）；要判断、要创意的部分归你或人。

`skill register <源目录> --force` 一并同步到注册表与各 agent。
